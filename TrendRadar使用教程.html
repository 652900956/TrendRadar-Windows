一、项目是什么 / 核心原理

一句话：TrendRadar 是一个 AI 舆情/热点监控工具——自动抓取各大平台热榜 + RSS 订阅，按你设定的关键词筛选，再用 AI 做分析/翻译，最后推送到飞书/微信/邮件等渠道。

核心原理：广抓取 → 窄筛选 → 增强 → 推送

① 抓取层  platforms.sources + rss.feeds
   └─ 去几十个热榜平台 + RSS 源 拉【全量】数据
   ↓  （这一步是"广"的，你配的平台全部拉）
② 筛选层  frequency_words.txt（关键词）或 AI 智能判相关
   └─ 【只保留命中你关键词】的内容，没命中的直接丢弃，不推送
   ↓  （这一步是"窄"的，是"推什么"的核心）
③ 增强层  ai_analysis + ai_translation
   └─ 对筛出的内容用 DeepSeek 做智能分析 + 多语言翻译
   ↓
④ 推送层  notification.channels + display.regions
   └─ 按配置推到飞书群等渠道，并生成 output/ 下的 HTML 报告
关键结论：抓取是"广"的（你配的平台全拉），推送是"窄"的——只有标题命中你关键词的新闻才会进飞书。不是热榜有啥都推，是你自定义方向命中的才推。

它抓取的是"我自定义的方向"还是"热榜全推"？

环节范围由谁控制
去哪些平台抓你列的平台全抓（广）platforms.sources
最终推什么只推命中关键词的（窄）frequency_words.txt / AI 筛选

二、三种部署方式怎么选

2.1 方式对比表

部署方式适合谁优点缺点自动运行靠谁
本地 Windows（当前）想用现成电脑、不想买服务器零服务器成本；文件都在本地；改配置方便电脑要开机；需配 Windows 任务计划Windows 任务计划程序
GitHub Actions想云端自动跑、电脑不常开不用服务器；GitHub 托管；自动定时敏感信息要上云 Secrets；有 7 天签到机制；需 Public 或消耗 Actions 分钟GitHub Actions cron
Docker（服务器/NAS）有 NAS/VPS/长期开机的 Linux稳定长期运行；一键 compose up；数据持久化需服务器/NAS；对新手略复杂容器内 cron

2.2 磊哥当前状态：本地 Windows 已配好

你现在的项目已经可以用：双击 运行TrendRadar.bat 就跑一次。
要让它"到点自动推"，还差最后一步：Windows 任务计划程序。
GitHub Actions 可以作为备选云端方案，两者可共存，但推同一个群会重复。

三、Windows 本地运行（当前主推）

3.1 一键双击运行

文件位置：D:\Software\EditingTools\Programming\MyProtects\TrendRadar\运行TrendRadar.bat
直接双击即可。它会自动注入 DeepSeek Key、绕过沙箱垫片、运行、跑完暂停。
双击后黑窗口要联网跑 1–3 分钟，别急着关。跑完显示"运行结束，按任意键关闭"。

3.2 手动命令运行

cd /d D:\Software\EditingTools\Programming\MyProtects\TrendRadar
set AI_API_KEY=sk-你的key
uv run python -m trendradar

（uv 在 %LOCALAPPDATA%\uv\uv.exe，已加入用户 PATH）

常用诊断命令

命令作用

uv run python -m trendradar --show-schedule显示当前调度状态

3.3 Windows 任务计划自动推送

项目自带 schedule 调度系统（在 config.yaml 里 schedule.enabled: true），但它只决定"这次运行该不该采集/分析/推送"。要让程序周期性地被唤醒，还需要 Windows 任务计划程序。

通俗理解：TrendRadar 像一位"临时工"，每次来干完活就走。Windows 任务计划程序是"闹钟"，每隔 30 分钟敲一次，叫醒他来干活。

创建步骤（管理员权限）

1. 按 Win + S，搜索"任务计划程序"，右键以管理员身份运行
2. 右侧点"创建任务"
3. 常规：名称填 TrendRadar自动推送；勾选"不管用户是否登录都要运行"、"使用最高权限运行"
4. 触发器：新建 → 开始任务"按预定计划" → 每天 → 重复任务间隔"30 分钟"，持续时间"1 天"
5. 操作：新建 → 操作"启动程序" → 程序或脚本填：
D:\Software\EditingTools\Programming\MyProtects\TrendRadar\运行TrendRadar.bat
6. 条件/设置：可勾选"如果任务运行时间超过"10 分钟则停止；勾选"如果过了计划开始时间，立即启动任务"
7. 点"确定"，输入 Windows 密码保存
权限注意：普通窗口创建任务可能报"拒绝访问"，必须用管理员身份打开任务计划程序。

四、GitHub Actions 无服务器部署（备选）

4.1 优点与限制

优点限制
不用电脑开机，云端自动跑需把 API Key、Webhook URL 放到 GitHub Secrets（敏感信息上云）
Public 仓库不计 Actions 分钟Private 仓库消耗账号套餐 Actions 分钟数
配置好后就自动定时必须每 7 天手动"签到"一次，否则自动停止

4.2 部署步骤

1. 打开 官方仓库，点绿色按钮 Use this template → Create a new repository（不要点 Fork）
2. 仓库名自定义（如 my-trendradar），可见性选 Public 免费或 Private（消耗 Actions 分钟）
3. 进入仓库 → Settings → Secrets and variables → Actions → New repository secret
4. 按下面表格逐个添加 Secret（名称必须完全一致）
5. 进入 Actions 页 → 左侧 Get Hot News → Run workflow → 手动运行测试
6. 收到飞书消息后，去 .github/workflows/crawler.yml 改 cron 表达式调频率

4.3 7 天签到机制

这是 GitHub Actions 部署必须了解的规则。
项目为了防止无人使用的定时任务空转浪费 GitHub 资源，设置了 7 天签到：超过 7 天不手动运行 Check In 工作流，Get Hot News 会被自动禁用，推送停止。

签到方法：

1. 进入你的仓库 Actions 页面
2. 左侧找到 Check In
3. 点 Run workflow → Run workflow
4. 如果 Get Hot News 已被禁用，回到该工作流点 Enable workflow

如果你不想每 7 天签到，建议改用本地 Windows 任务计划或 Docker。

修改运行频率

编辑仓库里的 .github/workflows/crawler.yml，找到：

on:
  schedule:
    - cron: '0 */2 * * *'  # 每 2 小时运行一次

改成你想要的 cron 表达式。注意 GitHub Actions 用 UTC 时区，北京时间要减 8 小时。

需求cron（UTC）北京时间
每小时0 * * * *每小时的第 0 分钟
每 30 分钟*/30 * * * *每小时的 0/30 分
每天 8:00 和 20:000 0,12 * * *8:00 / 20:00
工作日每 2 小时0 0-14/2 * * 1-5周一到周五 8:00-22:00

七、config.yaml 详解

7.1 热榜平台配置

配置位置：config/config.yaml 的 platforms 段。

platforms:
  enabled: true
  sources:
    - id: "toutiao"
      name: "今日头条"
      expected_domain: "toutiao.com"
    - id: "weibo"
      name: "微博"
      expected_domain: "weibo.com"
    # 想去掉某个平台：直接删掉（或注释掉）那 3 行即可

字段说明：

字段必填说明
enabled是总开关，true 启用热榜抓取，false 关闭全部热榜
id是平台标识符，必须来自 NewsNow 支持的列表
name是显示名称，会出现在推送里
expected_domain否域名校验，防链接被篡改，建议保留

如何找平台 ID：

  1. 访问 NewsNow 在线预览，点"更多"查看所有平台
  2. 或看 NewsNow 源码 server/sources 目录
  3. 或看社区整理清单 Issue #95
建议：平台数量控制在 10-15 个，太多会信息过载。当前磊哥配置了 43 个平台，其中部分带 disable: cf 的可能会因 Cloudflare 防护抓不到，TrendRadar 会自动跳过失败项。

7.2 RSS 订阅配置

配置位置：config/config.yaml 的 rss 段。

rss:
  enabled: true
  freshness_filter:
    enabled: true
    max_age_days: 1
  feeds:
    - id: "hacker-news"
      name: "Hacker News"
      url: "https://hnrss.org/frontpage"
    - id: "my-blog"
      name: "我的博客"
      url: "https://example.com/feed.xml"
      enabled: true
      max_age_days: 7
字段必填说明
enabled是RSS 总开关
id是唯一标识符，不能重复
name是显示名称
url是RSS/Atom/JSON Feed 地址
enabled（单源）否默认 true，设为 false 临时禁用
max_age_days否覆盖全局新鲜度过滤，0 表示不过滤
新鲜度过滤：只在推送阶段生效，抓取到的所有文章仍会存入数据库。全局默认 max_age_days: 1 表示只推 1 天内的。

7.3 筛选方式：关键词 vs AI

filter:
  method: "keyword"   # keyword=按词筛(不耗token) / ai=AI智能判相关(耗token)
  • keyword：用 frequency_words.txt 匹配，不调用 AI、不烧钱，规则固定 → 推荐日常用
  • ai：让 AI 读标题判你是否感兴趣，更灵活但每次运行消耗 token，兴趣描述写在 config/ai_interests.txt

7.4 AI 模型配置

ai:
  model: "deepseek/deepseek-chat"   # 模型标识
  api_key: ""                        # 留空，用环境变量 AI_API_KEY 注入
  api_base: "https://api.deepseek.com"
  timeout: 120
  temperature: 1.0
  max_tokens: 5000

模型标识格式：必须包含斜杠 提供商前缀/模型ID。

想用写法
DeepSeek（当前）deepseek/deepseek-chat
DeepSeek Flash（更快更便宜）deepseek/deepseek-v4-flash
OpenAIopenai/gpt-4o
Geminigemini/gemini-2.5-flash
本地 Ollamaollama_chat/模型名
你的 Key 是 DeepSeek 的。换非 DeepSeek 模型需要对应服务商的 Key。本地 Windows 部署时，Key 通过 运行TrendRadar.bat 里的环境变量注入，不写在 config.yaml 里。

7.5 推送渠道配置

配置位置：config/config.yaml 的 notification.channels 段。

notification:
  enabled: true
  channels:
    feishu:
      webhook_url: "https://open.feishu.cn/.../hook/xxxx"
    dingtalk:
      webhook_url: ""
    wework:
      webhook_url: ""
    telegram:
      bot_token: ""
      chat_id: ""
    email:
      from: ""
      password: ""
      to: ""
    ntfy:
      topic: ""
    bark:
      url: ""
    slack:
      webhook_url: ""
    generic_webhook:
      url: ""

填了 webhook 的渠道才会收到推送；留空的不推。Webhook 是半公开凭证，别发到公开仓库。

多账号推送

同一渠道可向多个接收方推送，Secret/配置值中用英文分号 ; 分隔：

feishu:
  webhook_url: "https://open.feishu.cn/.../hook/aaa;https://open.feishu.cn/.../hook/bbb"

7.6 显示区域与推送模式

显示区域

display:
  region_order:
    - new_items
    - hotlist
    - rss
    - standalone
    - ai_analysis
  regions:
    hotlist: true        # 热榜筛选结果区
    rss: true             # RSS 区
    ai_analysis: true     # AI 分析区
    new_items: false      # 新增热点区
    standalone: false     # 独立展示区（不受关键词过滤）

一个区域要显示，必须同时满足：在 region_order 里 + 在 regions 中设为 true。

独立展示区 standalone

用于将指定平台或 RSS 源的内容完整展示，不受关键词过滤影响：

display:
  regions:
    standalone: true
  standalone:
    platforms: ["zhihu", "wallstreetcn-hot"]
    rss_feeds: []
    max_items: 20

推送模式

report:
  mode: "current"   # current=在榜就推 / incremental=只推新增(零重复) / daily=当日汇总
模式推送时机内容适用
daily定时推送当天所有匹配新闻（会重复）回顾全天趋势
current定时推送当前榜单中匹配的新闻（在榜就重复）追踪当前热门
incremental仅新增时只推第一次出现的新闻（零重复）零噪音监控

显示分组方式

report:
  display_mode: "keyword"   # keyword=按关键词分组 / platform=按平台分组

7.7 调度系统 schedule

schedule:
  enabled: true
  preset: "morning_evening"

preset 可选值：参考 config/timeline.yaml 里的预设名称。

预设含义
always_on全天监控，有新增加即推送
morning_evening早晚汇总，白天推送+晚间汇总（推荐）
office_hours工作时段三段式推送
night_owl夜间工作模式
custom完全自定义

八、frequency_words.txt 关键词配置

这个文件决定"推什么"。分两个区：

区作用
[GLOBAL_FILTER]全局屏蔽词——含这些词的新闻直接丢弃
[WORD_GROUPS]你想关注的关键词组——命中才进推送

关键词格式速查表

写法含义示例匹配效果
华为普通关键词华为标题含"华为"即匹配
/正则/正则表达式/华为|鸿蒙|任正非/含三者任一即匹配
词 => 别名显示别名/华为|鸿蒙/ => 华为显示为"华为"分组
[组名]词组名[华为]该组统一显示"华为"
+词必须词+苹果
+发布会		必须同时含"苹果"和"发布会"
!词排除词苹果
!水果		含"苹果"但排除含"水果"
@数字该组最多显示几条@5该组最多推 5 条

正确写法示例

[WORD_GROUPS]

# 最简单：直接写词
华为

# 一组多个词，并起组名
[华为]
华为
鸿蒙
任正非

# 用正则一行搞定多个同义词
/华为|鸿蒙|任正非/ => 华为

# 精确匹配英文单词
/\bAI\b/i => AI

# 必须同时包含两个词
+苹果
+发布会

# 排除某些场景
[苹果公司]
苹果
!水果
!果园

常见错误

错误正确
写 华为，鸿蒙（逗号隔开）每个词单独一行
不加 / 直接写正则 华为|鸿蒙正则必须包 /.../
把关键词写在 # 后面# 开头是注释，不生效
组名写成 (华为)组名用方括号 [华为]

九、timeline.yaml 调度系统

控制"每天不同时间段该做什么"。每个时间段可以独立设置采集、分析、推送、过滤方式、AI 模式。

预设模板

在 config/config.yaml 里选 schedule.preset 即可套用。

预设适合场景
always_on全天候监控，有新增即推送
morning_evening早晚汇总，适合大多数人
office_hours工作日三段式推送
night_owl午后+深夜，适合夜间工作
custom完全自定义

自定义时间段示例

presets:
  custom:
    periods:
      morning:
        start: "08:00"
        end: "10:00"
        collect: true
        analyze: true
        push: true
        filter: keyword
        analysis: incremental
      evening:
        start: "19:00"
        end: "21:00"
        collect: true
        analyze: true
        push: true
        filter: ai
        analysis: daily
    default:
      collect: true
      analyze: false
      push: false

字段说明：

字段说明
start/end时间段起止，24小时制
collect是否采集数据
analyze是否调用 AI 分析
push是否推送
filterkeyword 或 ai
analysisfollow_report/daily/current/incremental

十、AI 功能详解

10.1 AI 分析推送

让 DeepSeek 分析抓取到的热点，生成洞察报告附在推送里。

ai_analysis:
  enabled: true
  language: "Chinese"
  max_news_for_analysis: 150
  include_rss: false
  include_standalone: true
  include_rank_timeline: true

AI 分析的五个板块：

  1. 核心热点与舆情态势：提炼当前最受关注的话题方向
  2. 舆论风向与争议：情绪走向、观点分布、争议焦点
  3. 异动与弱信号：异常波动和早期迹象
  4. RSS 深度洞察：对 RSS 内容的深度分析
  5. 研判与策略建议：发展走向和应对建议

AI 分析模式（可在 timeline.yaml 按时间段设置）：

模式分析范围
follow_report跟随 report.mode 的值
daily全天数据
current当前榜单快照
incremental仅新增条目

AI 开关（本地便利工具）

不想调用 DeepSeek 时，双击 切换AI开关.bat 即可把 ai_analysis.enabled 和 ai_translation.enabled 同时打开或关闭。

  • 关闭后：只抓取热榜 + RSS → 按关键词筛选 → 推送，不消耗 token。
  • 再次双击：恢复 AI 分析和翻译。
  • 每次切换前会自动备份 config/config.yaml.bak。

10.2 AI 智能筛选

用自然语言描述兴趣，让 AI 自动判断新闻是否相关。

# config/ai_interests.txt
我对以下领域感兴趣：
1. AI 技术发展动态，包括大模型、AI Agent、AI 应用落地
2. 电动汽车市场趋势，特别是特斯拉、比亚迪等头部品牌的动向
3. 中国重大政策变化，尤其是经济和科技政策
4. 半导体芯片行业的技术突破和产业链变动

不要标题党，不要营销软文。
# config/config.yaml
filter:
  method: ai

ai_filter:
  min_score: 0.7   # 0-1，越高越严格
阈值效果
0.3-0.4宽松，大部分通过
0.5-0.6适中，推荐大多数用户
0.7-0.8严格，只保留高度相关
0.9-1.0极严格，可能过少

10.3 AI 多语言翻译

ai_translation:
  enabled: true
  language: "English"
  scope:
    hotlist: false
    rss: true
    standalone: true

与 AI 分析共享模型配置，无需重复配 Key。支持任意语言名称。

十一、MCP 对话分析

MCP（Model Context Protocol）让 AI 助手能直接查询你本地收集的新闻数据，用对话方式提问。

能做什么

  • "今天有什么热门新闻？"
  • "分析一下最近一周关于人工智能的新闻趋势"
  • "对比微博和知乎上关于某话题的讨论热度"
  • "生成本周的新闻总结报告并推送到飞书"

部署方式

MCP Server 以独立 Docker 镜像提供，默认监听 3333 端口：

docker compose up -d trendradar-mcp

或在 AI 客户端（Cherry Studio/Claude/Cursor）配置 STDIO 模式：

{
  "mcpServers": {
    "trendradar": {
      "command": "uv",
      "args": ["run", "python", "-m", "mcp_server", "--transport", "stdio"],
      "cwd": "D:/Software/EditingTools/Programming/MyProtects/TrendRadar"
    }
  }
}

HTTP 模式

在 Cherry Studio 中添加 MCP Server：

  • 类型：streamableHttp
  • URL：http://127.0.0.1:3333/mcp

本地存储（当前默认）

十三、本地可视化配置编辑器

项目里 editor/config_editor.html 已按你的实际文件重写。双击用浏览器打开即可，打开就能看到你现在的真实配置，完全离线、数据不出浏览器。

它怎么工作的

  1. 内容自定义：左上角标签 = 你本地实际要编辑的配置文件（config.yaml / frequency_words.txt / timeline.yaml / ai_interests.txt / ai_analysis_prompt.txt / ai_translation_prompt.txt / ai_filter/prompt.txt）。
  2. 联动调节：左边是代码，右边是可视化面板。你在右边勾选平台、增删 RSS、改 AI 开关、编辑关键词组 —— 左边代码会实时跟着变；反过来你直接在左边改代码，右边表单也会刷新。
  3. 复制替换：调好后点左上「📋 复制代码」→ 去 config/ 目录把对应文件全选粘贴替换。也可点「⬇️ 下载」存成 .txt 再改名放回去。
  4. 定位与折叠：右边卡片标题 = 左边章节注释，点击标题左边自动跳到对应位置；标题右侧箭头可折叠/展开该区块。

防改坏保护

  • 这三个文件是彼此独立的配置文件，程序分别读取它们，不存在耦合。
  • 编辑器复制前会做 YAML 合法性校验：格式非法会弹红字警告并禁止复制。
  • 替换前建议先备份原文件（改名 .bak）。

十四、发布网页报告

每次运行后，TrendRadar 会在 output/html/ 生成网页版报告。

  • 最新报告：output/html/latest/current.html
  • 历史报告：按日期存放于 output/html/YYYY-MM-DD/

Docker 部署时，容器会启动内置 Web 服务器（默认 http://127.0.0.1:8080），可直接浏览器查看。本地 Windows 可直接双击 HTML 文件打开。

十五、多机器人 / 多实例说明

同一个飞书群添加第二个机器人

  • 可以：两个机器人用不同 webhook URL，互不影响。
  • 推到同一个群 → 消息重复。
  • 推到不同群 → 互不干扰。
  • 本地文件不冲突，因为 webhook URL 只是 config.yaml 里的一行字符串。

在其他 AI Agent（如 Codex）中重新部署到新文件夹

  • 不会冲突：新文件夹 = 独立代码、独立 venv、独立配置、独立数据库。
  • 注意：如果两个实例用同一个 webhook 推同一个群，会重复；用同一个 DeepSeek Key，费用翻倍。

本地 + GitHub Actions 同时运行

  • 可以共存，但推同一个群会重复。
  • 建议：本地推一个群，云端推另一个群；或二选一。

十六、故障排查

现象原因/解决
飞书没收到检查 notification.channels.feishu.webhook_url 是否正确；群是否还在；运行 --test-notification 测试
AI 报错/无分析确认 AI_API_KEY 已注入；ai_analysis.enabled: true；模型名是否正确
推送内容太多精简 frequency_words.txt；或改 report.mode: incremental
某些平台抓不到该平台接口波动或 Cloudflare 防护，属正常；可暂时注释掉该 source
GitHub Actions 不自动跑检查是否超过 7 天未签到；工作流是否被 Disable
Windows 任务计划不生效确认用管理员创建；触发器是否启用；bat 路径是否正确
RSS 源 404该源地址失效，换源或注释掉
